# QQbot 自动记忆与知识沉淀：第一版实现说明

状态：已实现可配置启用的第一版，真实 QQ/模型端到端测试尚未执行。开发没有修改真实配置、重启机器人或开启真实采集。

## 1. 最终范围

- 群聊仅正常模式下被现有 `matchMessage` 接受的 @ 问答；真实 at 段、文本 @ 别名沿用原规则。
- 私聊仅配置允许的白名单用户，不要求 @。
- 普通群聊、@ 他人、娱乐模式 @ 和主动插话不参与新系统的采集或检索。
- 新自动沉淀从每个范围实际开启后开始；重连补送旧消息不视为新交互，停用时段不回填。
- 保留读取已有 `remember` 长期记忆，但不回扫原始旧聊天、旧 session 或旧摘要。
- 各群、各用户私聊独立，没有跨域发布、全局搜索或共享知识池。同群个人背景按用户隔离。
- 宁少勿滥：自动提炼不要求每次产出，不把机器人回答当现实验证。

## 2. 与原设计相比的实际取舍

为避免群共享 session 残留个人背景，已接管范围不再续接 pi session，而由程序提供当前用户在当前范围的少量近期合格问答，并检索允许使用的条目。每次正常回答仍只调用一次模型，不做额外的个人润色调用。

第一版使用保守的可逐字对照证据规则，模型不能自由改写未经确认的结论。已有条目的更正要求真实用户明确提供条目 ID；尚不支持仅凭“做好了”自动找出并完成某个旧任务。复杂事项状态、会议到期判断、语义冲突合并、独立模型质量复核均为未实现部分，不应按完整状态机描述此版本。

一般技术解释先作为候选；带适用条件、明确本人确认/实测、愿意本群公开的经验才可进入群公共知识。此策略可能漏掉有价值的知识，但不会为了增加条目数量默认相信模型回答。

当前自动提炼只处理合格文字交互。附件与网页功能继续服务即时回答，但正文尚未作为独立知识来源接入；不能声称已自动沉淀整份文档或网页。

## 3. 启用和管理

`knowledge` 是独立配置，缺省关闭，不复用 `memory.windowMs`。配置允许范围与持久化开启策略必须同时满足。

```json
{
  "knowledge": {
    "enabled": false,
    "groups": [],
    "privateUsers": [],
    "automatic": true,
    "extractIntervalMs": 600000,
    "batchMaxMessages": 80,
    "batchMaxChars": 12000,
    "maxCallsPerScopePerHour": 6,
    "rawRetentionDays": 7,
    "candidateRetentionDays": 14,
    "retrievalMaxChars": 3000
  }
}
```

ID 必须是数字字符串，私聊允许列表必须是 `bot.whitelist` 子集；未知选项、非法数值和重复 ID 会被拒绝。配置变更需要重启，当前没有自动热更新 knowledge 配置。

确定性管理命令：

| 命令 | 行为 |
| --- | --- |
| 开启记忆 | 群限本机 owner，私聊限本人；告知第三方模型处理，持久记录起点 |
| 关闭记忆 | 停止本范围采集、提炼和历史注入，不删除已保存条目 |
| 记忆状态 | 查看当前范围开关及本人可见的状态，不列他人的个人资料 |
| 退出记忆 | 停止本人采集，并清除本人在当前范围的来源、条目和历史版本 |
| 恢复记忆 | 恢复之后的新交互，不复活删除数据、不补停用记录 |

群中所有命令都须 @。娱乐模式不管理这套记忆。首次接管后即使停用，也不回退到旧记忆来源。

## 4. 已有长期记忆接管

只读取启用私聊用户对应的 `memory/long-term/<QQ>.jsonl`，不扫描所有人的档案。普通旧条目允许缺少 `pinned`；解析、长度和敏感检查失败的条目不自动使用。

导入条目归属对应私聊，受众为 `subject_only`，标记 `legacy_unverified`。可在相关私聊中使用，但不能冒充已验证事实，更不能自动进入群。原文件保留且不改写。

保存一次性接管标记和来源键：重启不重复导入，删除不从旧文件恢复。旧文件后来新增的内容也不自动同步；接管后的记忆应通过新系统维护。未启用其他范围的旧行为不由此改造自动消失。

## 5. 程序结构

| 文件 | 职责 |
| --- | --- |
| `src/knowledge/types.ts` | 配置、可信输入、运行、来源、条目和候选类型 |
| `src/knowledge/policy.ts` | 范围、配置、敏感检测、操作意图与激活门槛 |
| `src/knowledge/store.ts` | SQLite、策略、来源、版本、检索、任务与删除 |
| `src/knowledge/service.ts` | 管理命令、旧记忆接管、受控上下文、单次运行授权和 RPC |
| `src/knowledge/extractor.ts` | 无工具提炼输入与严格 JSON/证据校验 |
| `src/knowledge/worker.ts` | 后台批次、预算、lease、重试、快速信号和维护 |
| `src/knowledge/bridge.ts` | 已匹配事件转可信输入，构造记忆权限提示 |
| `sandbox/.pi/extensions/knowledge-tools.ts` | 五个受限记忆工具的 RPC 客户端 |
| `sandbox/.pi/knowledge-guard.ts` | 旧扩展读取前检查保护列表，禁止间接读取已保护资料 |

`src/main.ts` 接入正常问答与撤回通知；`src/router.ts` 保留消息 ID、事件时间和接收时间；`src/runner.ts` 统一回答、摘要、合并与后台提炼的并发调度。

## 6. 存储与访问

数据库为 `memory/knowledge.sqlite`，主进程持有连接，扩展不能自行连接。现有 `memory/` 忽略规则覆盖数据库及 WAL，但备份也必须按私密内容处理。SQLite 默认不加密。

主要数据：scope/actor 策略、合格消息 sources、items/revisions/evidence、持久 jobs、model_calls、legacy_imports、删除 tombstone、无正文审计与 FTS 索引。schema 版本独立于内容接管，不等于历史聊天导入。

受众与范围：

| scope / audience | 使用范围 |
| --- | --- |
| `private:<QQ>` / `subject_only` | 该用户私聊 |
| `group:<群号>` / `subject_only` | 该用户在本群的相关问答 |
| `group:<群号>` / `group` | 本群已激活公共知识 |

查询在 SQL 中限制范围、主体和状态，不先把全库正文读出再过滤。全文检索使用 FTS5 trigram，短中文查询有范围内回退；普通问句提取有上限的检索词，MATCH 字符转义并绑定参数。

上下文预算默认约 3,000 字符：优先少量个人条目和相关有效知识，再加入本用户近期问答。敏感内容不自动注入。使用次数不能提升验证级别，引用旧记忆不等于重新确认。

## 7. 自动沉淀

```text
合格 @/私聊请求
    → 启用状态、身份、模式、时间、敏感检查
    → 保存用户原文与来源
    → 记录成功生成的回复，仅作上下文
    → 后台分批无工具提炼
    → JSON/schema/来源/逐字证据/权限校验
    → 候选或有限自动激活
```

模型输出仅允许 create/revise、类型、正文、适用条件和逐字证据等固定字段；不能指定 scope、用户身份、audience 或验证分数。

个人背景/偏好必须有可对照的本人表达；建议、猜测、引用他人和否定完成不升级为事实。否定偏好本身可以是有效记忆，如“我不喜欢厚教材”；不能因为同条消息里有否定句就丢弃另一句明确背景。

更正需要真实用户的明确意图、条目 ID 和当前版本；公共条目不允许通过更正降类成为公开的个人信息。版本竞争由 CAS 拒绝，不覆盖较新的人工更正。

默认每 10 分钟检查，明确记忆/进展线索及消息数量达到门槛可合并后提前检查。所有调用共享范围内预算，不逐条消息调用模型。

第一版回复记录表示成功生成的上下文，不代表 QQ 实际投递成功，不能将回复发送情况当知识验证。

## 8. 运行权限与工具

每次问答生成随机短期 token，在主进程绑定真实 actor、scope、来源、策略和过期时间。扩展通过 loopback POST 与 `Authorization: Bearer` 调用，不能自报 QQ 或群号扩大权限。结束、退出、撤回和过期后 token 失效。

受限工具：`memory_search / memory_get / memory_save / memory_correct / memory_forget`。保存、更正、删除必须有本次真实用户明确意图；删除还要求唯一明确条目 ID，不能把模型猜测当授权。工具真实结果区分激活、仅候选和失败。

启用记忆的模型白名单：联网、时间及上述五项工具。旧 remember/recall/forget、任意群日志、跨域发送、任务管理和外部助手桥不开放。原有确定性命令、独立定时任务不因此删除，但不给新库凭据。

旧工具还有反向保护：桥接为所有模型任务传入配置允许接管及已接管的群/用户 ID，旧 chat_digest 不读取或枚举这些群的日志，旧记忆工具不读写这些用户的文件。保护列表从启用配置时就存在，避免在开启命令之前排队的旧任务后来绕过新边界；保护是元数据，不授予新库检索权限。未列入保护的旧范围保留原有行为。

已只读核验本机 `@earendil-works/pi-coding-agent 1.0.0` 的实际 bundle：工具白名单同时限制 builtin、extension 和 custom 工具，动态注册也受过滤。后台 none 模式另外使用 `--no-extensions`，清除显式扩展参数；不是仅仅隐藏工具描述。

工具限制不是 JS/操作系统沙箱：普通回答仍会加载可信扩展代码，当前系统账户能读取数据库。新库不向 full 模式提供凭据；若换成不同 pi 版本或额外危险扩展，必须重新验证工具和代码执行边界。

## 9. 后台调度与恢复

runner 队列：interactive > scheduled > background。后台最多一个；有交互等待时不新开后台，并发至少 2 时不占最后槽位；单并发时交互可取消后台，worker 有限重试。

后台调用无工具、无 session，有超时与 AbortSignal，排队时也可取消；凭据仅存在于对应 knowledge 任务，不通过全局环境串用。基础 CLI 权限参数规范化，拒绝会停止解析的 `--`。

任务持久保存来源/版本快照和 lease。事务提交前再次核验 scope、actor、epoch、来源版本和模式；撤回、删除、退出或人工更新后旧 worker 不能复活内容。格式错误、模型失败等有限重试，不把失败消息范围标成成功。

维护当前实现：原文期限清理、候选清理、预算记录清理、lease 恢复、索引及 WAL 清理。没有自动推断事项完成、任务到期或复杂知识时效的功能。

## 10. 删除与隐私边界

撤回通知按 message ID 关联，使来源及依赖知识退出使用；先收到撤回再收到消息也有 tombstone 防止重新入库。平台未提供撤回通知时无法保证自动同步。

忘记条目会清除正文、版本、证据和索引，并使关联来源失效；同一来源支持的其他条目可能一同失效，这是保守防复活策略。退出清除自己的来源和条目，不清除其他成员的独立资料。

数据库清理不承诺物理介质不可恢复，历史备份需另按保留与删除策略管理；已发送的 QQ 消息不会自动消失。原始交互的提炼可能发送给配置的外部模型服务，敏感检测不能保证零漏判。

既有群日志仍是独立功能，本版没有停止其普通消息记录；新系统不从它们抽取。不能把“不参与沉淀”宣传为“项目完全没保存这条群消息”。

## 11. 验证

```bash
npm run selftest:memory
```

- `scripts/runner-selftest.ts`：白名单、参数冲突、token 环境隔离、并发槽、取消、超时和 fixture 进程树。
- `scripts/knowledge-selftest.ts`：配置、权限、旧长期记忆接管、来源、质量、检索、CAS、lease、撤回删除和停用恢复。
- `scripts/knowledge-safety-selftest.ts`：公开条目更正不能泄漏个人内容、跨来源精确去重、条件/引语不升级、无正文审计、撤权后旧答案不能使用和未来 schema 保护。
- `scripts/legacy-guard-selftest.ts`：用合成旧日志验证已保护群/私聊不能被旧工具间接读取或枚举，未接管旧范围仍可用，非法 ID 和策略解析失败安全拒绝。
- `scripts/knowledge-integration-selftest.ts`：真实路由匹配到可信输入、管理命令、扩展到本地 RPC、近期问答隔离、撤回及示例配置。
- `scripts/bridge-smoke-selftest.ts`：复制源码到临时运行目录，使用合成配置、假的 OneBot WebSocket 服务和 fixture 模型执行真实 main 路径，验证启用、正常/娱乐切换、旧记忆私聊接管和关闭后不回退。

测试仅使用临时数据库、合成旧记忆和模拟模型/子进程，不读取真实聊天、不连接 QQ 或真实模型。当前验证环境 Node 24.15.0，未验证声明最低 Node 的全部数据库特性。

实际 pi 工具限制来自安装源码核验，参数与运行行为来自 fixture 测试；两者都不等于真实模型/QQ 端到端运行验证。该验证尚未执行，真实配置也未自动启用。
